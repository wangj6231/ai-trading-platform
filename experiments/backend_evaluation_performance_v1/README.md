# Backend evaluation performance V1 diagnostics

These scripts are opt-in diagnostics, not a production strategy or alternate verifier. Production uses the existing concrete engine. Complete result comparison uses the repository's `canonical_sha256` snapshot utility with exact values.

`capture_baseline.py` is one-shot and refuses to overwrite its source snapshot. Run before modifying production. It records the existing dirty worktree, contract/source/frontend hashes and a real public-provider candle slice. Never replace this baseline with later live data.

`fixed_evaluation.py --baseline --label before` evaluates the preserved source and fixed input. Current-code runs use `--label loopN --comparison-identity`. The comparison-only identity is explicit: source edits legitimately change `algorithm_build_hash`, so actual identities are saved separately in metadata. Production never receives a pinned identity. `compare_fixed.py --label loopN` compares complete output and checks that frontend, config and schemas remain frozen.

`probe_server.py` starts the actual FastAPI app with normal Binance public-provider acquisition. `PERF_PROBE_LABEL` selects artifact names and `PERF_PROBE_PORT` the localhost port. Sampling and timing wrappers exist only here. `probe_requests.py --url http://127.0.0.1:8012 --label loopN --evaluation-timeout 120 --analysis` records idle requests, overlapping signal/health/candles/second signal, post-timeout health and analysis. A timeout is explicitly censored. Fixture tests never establish live performance.

Use `--symbol ETHUSDT` to probe that actual market. `capture_eth_history.py` preserves its own real provider history rather than relabelling BTC input. Its fixed reference is `fixed_evaluation.py --baseline --symbol ETHUSDT --label before_eth`; compare a current ETH label with `compare_fixed.py --label LABEL --before-label before_eth`.

`compare_api_projection.py --baseline [--symbol ETHUSDT]` invokes the preserved original routes over their full preserved engine result and fixed diagnostic provenance. The same command without `--baseline` checks both complete public projections against those canonical hashes. It does not call Binance or substitute a different strategy.

`probe_health_window.py --url URL --label LABEL --duration 150 --until LABEL_http.json` checks health throughout compute, IPC and response publication; a single early health request cannot establish that publication stays responsive. `probe_cancel.py --url URL --label final` closes two real requests after five seconds, checks the bounded-capacity technical error and then completes another signal. `probe_resources.ps1` records the owned web process and its actual children, CPU, memory and thread IDs. Its first cancellation-window artifact contains PID 0/null-child entries from an empty-list enumeration diagnostic bug; those entries are excluded from interpretation, and the corrected after-cancel idle window confirms no children and no CPU work.

Final uninstrumented requests use the ordinary `uvicorn app.main:app` entry point, without stack/timing wrappers. Measurements are local Windows observations with hydrated public historical caches and fresh evaluation workers; they are not an uncached Binance history bootstrap or a production load SLA. `summarize_evidence.py` aggregates recorded artifacts and the final regression XML, verifies frozen files and uses existing comparison results; it performs no new strategy comparison or evaluation.

From LOOP 18, application readiness preinitializes up to two one-use workers. Ready, initializing and active workers share the same process bound. Each runs one complete evaluation, then is reaped and replaced. Two idle workers after completion are expected; their initialization is bounded and they perform no market acquisition or strategy evaluation. Resource interpretation distinguishes replaced PIDs from old evaluation PIDs. Source-universe byte/module-path checkpoints cover both initialization and the wait before execution; drift is a technical error. The unchanged original source-identity builder remains authoritative.

From LOOP 20, only an active evaluation can be shared. Every caller independently acquires and validates evidence; all source/config/build/mode key dimensions must match. Each member retains its own provenance and fully validated public projection. The worker validates exact full context equality, publishes signal before analysis, and is owned by the remaining waiters. No completed result survives for reuse. Zero waiters and shutdown cancel and await reaping. Admission remains bounded to two requests.

`fixed_evaluation.py --disable-auto-gc` explicitly mirrors the one-use worker's automatic cycle-scan policy; `--gc-events` records generation-level callbacks. Reference counting remains enabled, and the web process's GC policy is unchanged. `profile_current.py --label LABEL --disable-auto-gc` records an external profile with profiling overhead; those timings are not live latency. `probe_serialization.py` performs complete real-result ABBA measurements and exact raw-byte hashes. HTTP measurements separately record complete body arrival and client JSON parsing; the original frontend deadline covers body arrival and remains 10 seconds. Synchronous stage records include GC state and, after LOOP 20's initial probe, process CPU time. Do not attribute host-load variance to a change without measured support.

Large provider histories, full outputs and preserved duplicate sources remain local/ignored. Metadata, HTTP/stage measurements, scripts and the root report remain reviewable. Do not publish credential-bearing runtime settings or unrelated datasets. Temporary localhost probe servers and cancelled workers are cleaned up by this task.
