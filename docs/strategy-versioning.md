# Deterministic strategy versioning

This project identifies every deterministic analysis with one server-generated
`StrategyIdentity`. The identity is provenance metadata, not evidence that a
strategy is profitable, validated, or safe for live order execution.

## Canonical `StrategyConfig`

`config/strategy.yaml` is the only trusted strategy-parameter file. The strict,
frozen `StrategyConfig` model owns the complete symbol pipelines for indicators,
market structure, liquidity, FVG/IFVG, order blocks, displacement, the ICT entry
setup, multi-timeframe alignment, signal scoring, risk and CRT. It also owns the
global deterministic backtest execution policy and its spread, normal-slippage
and commission parameters. Unknown fields, invalid ranges and contradictory
cross-field combinations fail validation.

Application startup loads this file once. The resulting value is shared with the
live/research deterministic engine and the signal persistence authority. The
backtester receives the same concrete engine; it does not load another strategy
file or maintain a second strategy implementation.

`canonical_strategy_config(config)` converts the typed model to UTF-8 JSON with:

- sorted mapping keys;
- stable compact separators;
- enum values instead of runtime enum objects;
- normalized finite decimal strings (`0.20` and `0.2` serialize identically);
- preserved list order where order has strategy meaning.

The schema has no timestamp, secret, database URL, API key, absolute path or
runtime identifier field. The serializer rejects timestamps, secrets, paths and
non-finite numbers rather than silently serializing them.

## Identity fields

### `strategy_version`

`strategy_version` identifies the deterministic ruleset/config-schema family.
It is the server constant `deterministic-smc-ict-v1`; no API, backtest or
persistence request can supply or override it.

It proves which ruleset family the server declared. It does **not** identify the
exact parameters, prove that the implementation matches a publication, or prove
empirical validity.

### `config_hash`

`config_hash` is SHA-256 of the canonical bytes of the complete validated
`StrategyConfig`, including every configured symbol pipeline. A single
strategy- or execution-affecting parameter change changes this hash; YAML key
reordering and equivalent decimal spelling do not.

It proves exact canonical-config equality. It does **not** prove that the inputs
were correct, that the strategy is profitable, or which source code executed.

### `algorithm_build_hash`

`algorithm_build_hash` is generated by the single server-owned build-identity
authority in `backend/app/core/algorithm_identity.py`. Git `HEAD` is not an
algorithm identity. Version 3 identifies the actual relevant source bytes in the
working tree, including staged, unstaged and relevant untracked Python files.

The manifest discovers every `*.py` below these broad runtime roots:

- `backend/app/engines/**`;
- `backend/app/backtesting/**`;
- `backend/app/schemas/**`;
- `backend/app/market_data/**`.

It also uses the shared strategy/build identity files and deterministic
evaluation/snapshot boundary files as explicit seeds. Manifest version 2 then
walks the statically imported local `app.*` dependency closure from every seed.
This covers absolute imports, package-relative imports, re-exporting
`__init__.py` modules and recursive helper imports. Consequently a new helper
extracted outside a broad seed root is automatically included when covered code
imports it. The current tree has no dynamic module-loading path in deterministic
research execution; any future dynamic dependency must be added as an explicit
seed/root and tested before use.

This policy explicitly treats time/cutoff semantics in `core/time.py`, financial
outcome semantics in `core/financial.py`, and research result semantics in
`metrics/financial.py` as algorithm relevant. Unreferenced backend helpers
outside the seed roots, tests, documentation, caches, logs, databases,
environment files, secrets, generated reports, frontend files, migrations and
build output are excluded. `config/strategy.yaml` remains represented only by
`config_hash`.

Each file is named by repository-relative POSIX path. Absolute checkout paths,
machine users and branch names never participate. UTF-8 source is decoded
strictly, an optional UTF-8 BOM is removed, and CRLF/CR are normalized to LF.
No other content normalization occurs. Entries are sorted by canonical path;
each stores SHA-256 of normalized content. Source deletion, rename or content
change therefore changes the manifest. mtime, ctime, permissions and filesystem
enumeration order never enter the hash. A required unreadable file, missing root,
missing imported local module, invalid UTF-8/syntax file, symlinked source or path
escape fails explicitly rather than creating a partial trusted identity.

The exact formulas are:

```text
source_content_hash = SHA-256(
  canonical JSON {
    source_manifest_schema_version: "2",
    entries: [{relative_path, content_sha256}, ...]
  }
)

algorithm_build_hash = SHA-256(
  canonical JSON {
    algorithm_identity_schema_version: "3",
    source_content_hash: source_content_hash
  }
)
```

There is no aggressive process cache: every identity request reads the current
runtime source. Identical relevant source in different checkouts or commits has
the same build identity; different dirty contents at the same `HEAD` do not.

Git remains separate server-generated provenance. The authority reports whether
usable repository metadata is available, the commit SHA when available, and the
whole-worktree dirty flag. These values explain repository history but are not
part of algorithm equivalence; branch name is neither required nor hashed. Git
absence or command failure leaves provenance unavailable while the strong source
content identity still works.

Version 1 and version 2 historical hashes are not recomputed or rewritten. The
version-3 scheme identifier is inside the canonical build-hash preimage and
manifest version 2 identifies the dependency-closure policy at this cutover.
Existing database and Snapshot V2 fields remain immutable opaque 64-character
hashes; all new evaluations use scheme 3.

This proves equality of the covered project source under the documented
canonicalization. It does **not** prove dependency, interpreter,
operating-system or external-provider equality, nor does it certify correctness.

### `analysis_snapshot_hash`

`analysis_snapshot_hash` is SHA-256 of the canonical stored Snapshot V2 JSON. It
detects changes to the captured point-in-time reasoning and embedded canonical
strategy manifest. ORM guards and PostgreSQL triggers separately prevent updates
after creation.

It proves stored snapshot byte-equivalence under canonical JSON. It does **not**
prove market-data authenticity, absence of upstream vendor errors, profitability
or future performance.

## Reproducibility chain

```text
Historical Signal
  -> StrategyIdentity
       -> strategy_version (ruleset family)
       -> config_hash (exact canonical StrategyConfig)
       -> algorithm_build_hash (scheme 3 actual-source identity)
  -> analysis_snapshot_hash
       -> immutable Snapshot V2
       -> point-in-time indicators, structure, SMC/ICT, MTF, score and risk
       -> embedded canonical StrategyConfig
```

To reproduce a historical decision, obtain the exact config matching
`config_hash`, the build matching `algorithm_build_hash`, and the immutable
analysis snapshot/data cutoff. Matching identity values are necessary provenance;
they are not a guarantee that external runtime dependencies or market-data vendor
responses are identical.

## Risk-target contract cleanup

The unsupported `risk.same_bar_resolution` field was removed from the strict
canonical strategy schema. It previously changed `config_hash` despite having no
Risk Engine or lifecycle consumer and exposed the unsafe `TARGET_FIRST` value.
New configuration containing that field, `TARGET_FIRST`, `FIXED_RR`, or a fixed-RR
ratio fails validation; it is not silently ignored or mapped to another behavior.

This cleanup changes the canonical bytes and thus the `config_hash` of new
evaluations even though the effective deterministic trading rules and parameter
values did not change. Historical `config_hash`, Snapshot V2 and persisted signal
identity fields remain immutable and are never reinterpreted. Effective
same-candle research behavior remains explicit in `BacktestRunSpec`, so changing
`AMBIGUOUS` to the already-supported `CONSERVATIVE_STOP_FIRST` changes the
BacktestRunIdentity without pretending to change Risk target selection.
